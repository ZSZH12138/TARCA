# TARCA 协议变更控制记录 CCP-0004

> 状态：`IMPLEMENTED_AND_CLOSED_PASS`
> 授权日期：2026-08-30
> 稳定协议身份：`TARCA-E2E-STAGE-PROTOCOL-2.0`
> 变更性质：E01-A 稳定性门禁校准与 E01-B 证据继承

## 1. 用户决定

用户确认采用 E01-v2。E01-v1 的运行事实和总门禁失败保持不可变；用于判定的 v1 最终报告与
回收验证以原字节 Base64 和各自 SHA-256 封装为唯一历史记录。已经通过的 Lorenz-96 E01-B
不重复运行，只允许在精确哈希和完整性验证通过后并入 v2。E01-v2 只重新运行解析环境 E01-A。

本授权允许在任何新正式结果产生以前修改E01-A的Gate定义，因为原五种子“最大样本误差必须
小于最小样本误差的一半”对理想蒙特卡洛估计器有较高偶然误拒风险。旧指标保留为诊断，不能
删除或改写其历史失败事实。

## 2. E01-v2冻结身份

- 正式分区：`TEST`；
- 种子：SHA-256命名空间`tarca/e01-v2/formal-test`确定性产生50个新种子；
- E01-v1五个种子全部排除；
- 嵌套样本量：32至8192的二倍序列；
- 解析世界、正确SCM、错误SCM、错误lag、随机概念与IDENTITY语义保持不变；
- 最大样本结果不得反向用于选择种子、阈值或配置。

## 3. E01-A-v2门禁

E01-A-v2必须同时满足：50个种子中至少45个95%区间覆盖精确真值；至少45个MCSE收缩比
不高于0.25；至少45个最终区间半宽不高于真效应的1%；50个最终点估计的平均偏差不高于
真效应的0.5%；lag、三种负对照和精确零IDENTITY各至少45个种子通过。

E01-v1的逐种子端点误差减半只作诊断，不参与E01-v2 PASS。

## 4. E01-B继承门禁

继承必须验证服务器回收档案、最终报告、科学配置、Stage1B v2冻结、SQLite完整性、166个
完成任务、零运行警报、E01-B五个收敛种子及三种方向性对照各五个种子。任一哈希、计数或
状态不符均fail closed，禁止以人工说明替代证据。

## 5. 整体判定与边界

`E01-v2 PASS = E01-A-v2全部门禁通过 AND E01-B继承凭据有效`。本变更提高正确方法通过
稳定性检测的校准度，但不保证任何具体运行必然通过，也不放宽Stage2及后续因果抽象、定位、
zero-refit或跨域Gate。

服务器只改变执行并发，不得改变上述科学身份。正式点火仍需要与连接、上传和预检分开的用户
确认：`I_ACKNOWLEDGE_E01_V2_FORMAL_RUN`。

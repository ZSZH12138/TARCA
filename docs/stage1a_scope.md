# TARCA Stage 1A 范围与交接

## 1. 本阶段解决什么问题

Stage 1A 建立全项目共用的“数据与结果语言”。后续模块不再自行猜测数据字段、张量形状、模型接口或结果表结构，而是依赖 `src/tarca/contracts/` 中同一套版本化契约。

本阶段只建立边界和最小可运行证据，不下载正式数据、不生成正式合成数据、不训练模型、不执行模型内部干预，也不产生可以支撑科学结论的实验结果。

## 2. 已建立的功能边界

- 数据身份：registry 必须精确命中 `(name, version)`，并以实际 SHA-256 绑定持久化载荷。
- 数据读取：只读取请求的既有物理分区；不自动归一化、补值、滑窗、打乱、转换 dtype 或重新切分。
- sealed 权限：registry 与调用范围共同决定是否受保护；授权必须在任何载荷 I/O 前匹配数据、范围、分区和有效期。
- 运行时数据：`WindowBatch` 固定形状、字段名、掩码、UTC 时间边界、dtype 和 device，并以身份保持校验证明验证器没有偷偷复制或转换 Tensor。
- 模型接入：预测器、机制适配器和概念提取器通过 Protocol 接入，不绑定某个具体模型实现。
- 结果格式：预测、干预配对、效应、指标和定位轨迹使用五套固定 Arrow Schema。
- 结果保存：类型化 ArtifactStore 在返回引用前完成临时写入、flush/fsync、hash、重读、Schema 校验以及数据与 manifest 的原子发布。

## 3. Stage 1A 与 Stage 1B 的分工

Stage 1A 负责制定和验证“容器、接口与通道”，回答数据怎样被识别、读取、检查和交接。

Stage 1B 才负责把合成 SCM 世界装入这些容器，生成带有可核验真值的数据、normalization 记录、物理切分和 `SCMTruthManifest`。因此 Stage 1A 可以在没有正式数据和训练的情况下先冻结接口，Stage 1B 则能在稳定边界上实现科学数据生成，不必一边生成数据一边修改全项目协议。

## 4. 权威与冻结规则

如有冲突，按协议声明的层级处理：项目计划书决定研究问题和 Gate；端到端协议决定跨阶段 I/O、类型和标准函数；冻结的 Stage 0 研究契约约束 Stage 1+ 正式实验；实施计划指导具体执行。代码不能因为“能够运行”而覆盖上位文档。

合并后，权威文档、冻结研究输入、Stage 0 制品、环境锁、Stage 0/Stage 1A 契约与边界代码、对应检查脚本和测试会设置 Windows 只读属性。没有用户明确授权时不得修改；获得授权后，应先解除目标文件只读、记录原因并在需要时归档旧制品和重算 hash，完成后恢复只读。

## 5. 最小验收入口

```powershell
.\.venv\Scripts\python.exe scripts/check_stage1a.py --json
```

该检查只读取并核对 Stage 0 交接、版本常量、五类 Arrow Schema、必要边界文件和冻结目录，不写正式数据，不创建协议未定义的 Stage 1A 完成凭证。
